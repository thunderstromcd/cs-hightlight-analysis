# 部署拆片

在装有录像和 CS2 的 Windows 主机上运行。需要 Node.js 24 或更新版本。服务在 `127.0.0.1:38471` 监听。本机浏览器打开 [拆片](http://127.0.0.1:38471)。

## 首次启动或从口令版升级

先停止 38471 的旧服务和导出任务。以下命令在项目目录运行。如果现有服务使用 `DATA_DIR`，运行命令和启动服务时使用同一个值。

```powershell
npm install
npm run account:admin -- 管理员用户名
npm run build
npm start
```

按提示输入新密码。命令先把旧录像和成片复制到 `data/backups/before-accounts-*`，再在 SQLite 中把旧数据登记到首个管理员。重复执行会拒绝创建第二个首任管理员。若使用自定义 `DATA_DIR`，备份和 `accounts.sqlite` 都放在该目录下。管理员登录后，在「账户设置」为其他用户开通账号。

日常备份时先停服务，再复制完整 `DATA_DIR`。更新代码时先停服务，再构建和启动。构建会覆盖 `.next`，所以 38471 仍在运行时 `prebuild` 会阻止构建。

## 同源 HTTPS 反代

域名和有效证书就绪后，在启动进程设置 `PUBLIC_APP_ORIGIN` 为实际 HTTPS 源站地址，例如 `https://clips.example.com`。在 HTTPS 反代上保留公网 `Host`，覆盖 `X-Forwarded-Proto` 和 `X-Forwarded-For`，并将上游指向 `127.0.0.1:38471`。HTTP 入口只重定向到 HTTPS。上传请求上限至少容纳 1 GB 和 multipart 开销。

```caddy
clips.example.com {
    reverse_proxy 127.0.0.1:38471 {
        header_up Host {http.request.host}
        header_up X-Forwarded-Proto https
        header_up X-Forwarded-For {remote_host}
    }
}
```

公网隧道接入 HTTPS 反代。原明文 TCP 入口应在新域名联调通过后切换。

[Caddy 反代配置](https://caddyserver.com/docs/caddyfile/directives/reverse_proxy)

## 录像机

分析和勾选不需要 CS Demo Manager。导出调用本机已经装好的 `csdm`。找不到时，页面直接显示「录像机未就绪」，解析和勾选照常。这个仓库不会安装 `csdm` 或 CS2。

导出使用支持 `csdm analyze --json` 的 CS Demo Manager 3.21 或更新版本。拆片先确认录像机完成分析，再开始录制，避免缺少选手数据时录到固定观战镜头。
